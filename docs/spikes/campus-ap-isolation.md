# 校园 Wi-Fi 的 AP isolation 实测（Task 0.3）

> **状态：待你在现场跑。** 这一条我做不了 —— 它要求两台设备
> 同时连在校园那个 Wi-Fi 上，没有任何办法在这台机器上模拟。
>
> 好消息是现在只要 5 分钟，而且结论是一句话读出来的。

## 为什么要测

若校园 AP 开了 client isolation（同一个 AP 下的客户端互相不可见），
局域网直连就不成立 —— ICE 会一路退到中继，
**一对多分发从「同楼里几百 MB/s」变成「全部挤你家那条上行」**。
二期的 swarm 分发价值直接归零。

只影响二期。但这个答案会决定二期值不值得做，所以早知道早好。

## 怎么测

两台电脑，都连上校园 Wi-Fi（**必须是同一个 SSID，最好在同一间教室**）。

信令服务器用你部署好的那台；没部署也行，在 A 机上双击 `start-signaling.cmd`
起一个临时的，两台都用它打出来的地址。

### 1. 各自拿一份构建

```bash
./packaging/package.sh        # → dist/nexusp2p-win-x64.zip
```

把 zip 拷到两台机器上解压。**不需要装 .NET。**

### 2. A 机发送

随便找个文件，几十 MB 就够：

```bash
nexusp2p.exe send 随便一个文件.zip --signaling https://p2p.你的域名
```

它会打出九位文件码和分享链接。

### 3. B 机接收

```bash
nexusp2p.exe receive "<分享链接>" --dest D:\收到 --signaling https://p2p.你的域名
```

### 4. 读那一行

连上之后两端都会打出一行，**答案就在括号里**：

| 打出来的字样 | 含义 | 对二期意味着 |
|---|---|---|
| `已连接（同局域网直连）` | AP **没有**隔离 | ✅ swarm 分发成立，可以做 |
| `已连接（打洞成功，公网直连）` | AP 隔离了，但能绕公网打洞回来 | ⚠️ 走的是校园出口，不是内网速度 |
| `已连接（经服务器中继，速度受服务器上行带宽限制）` | AP 隔离且打洞失败 | ❌ swarm 无意义，全挤你家上行 |

顺便看一眼速度：同局域网直连应该有几十到几百 MB/s，
中继则不会超过你家宽带的上行。

## 如果结论是「被隔离」

不用改任何现有代码 —— 中继兜底本来就在。
只是二期的 swarm 分发要重新评估：在被隔离的网络里，
「一对多」等于「同一份数据从你家上行发 N 遍」，
那还不如让大家排队一个一个收。
