# 网络约束实测结论

> 对应 Task 0.1 / 0.3

## 443 端口：可用（2026-08-07 确认）

现有部署在同一台家用服务器上的网站正常运行，说明 443 未被运营商封锁。

**影响**：不需要非标端口。服务直接监听 443，分享链接是干净的
`https://域名/r/111111111#密钥`。

80 仍然被封，所以证书走 Let's Encrypt 的 **DNS-01** 验证。
TLS-ALPN-01 虽然用 443 因此技术上可行，但它需要在验证期间抢占 443、
与常驻服务冲突；DNS-01 不碰端口也不中断服务。

## UDP：未被 QoS 限速（2026-08-07 确认）

**影响**：这条解除了一个反直觉的风险。原本担心的是：若家宽的 UDP 被显著限速，
而中继可以走 TCP/TLS，那么**打洞成功反而可能比走中继更慢** ——
「直连优于中继」这个默认假设会被颠倒，瓶颈显示逻辑（Task 5.4）也要跟着改。

既然 UDP 正常，就可以维持原设计：

- 直连优先，打洞失败才落中继
- 瓶颈显示里「走中继中」意味着「速度受服务器上行限制」，
  而不需要处理「中继反而更快」这种反常情况

## 校园网 AP isolation：未测（Task 0.3）

仅影响二期的局域网 swarm。若校园 Wi-Fi 开了客户端隔离，
局域网直连失效、ICE 会退回中继，二期 swarm 的价值归零。

需要带两台设备到现场实测：互相 ping、建 TCP 连接。
不阻塞 MVP。
