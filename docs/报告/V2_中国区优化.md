## 2. 速率限制开关默认关闭

### 更新内容

**新增配置项**: `EnableJoinRateLimit`

```json
{
  "Signaling": {
    "EnableJoinRateLimit": false,  // 默认关闭
    "JoinAttemptsPerMinute": 100   // 开启时的限制次数
  }
}
```

### 为什么默认关闭？

#### ❌ 原来的问题
- 同一家庭网络多个设备同时下载被限速
- 企业内网多用户被误判为攻击
- 开发测试时频繁触发限速
- 影响正常用户体验

#### ✅ 现在的方案
- **默认关闭**: 开箱即用，不限制
- **灵活配置**: 生产环境可选开启
- **明确说明**: 配置文件有详细注释

### 何时需要开启？

#### 场景 A: 公开部署的服务器
```json
"EnableJoinRateLimit": true
```
**原因**: 防止暴力枚举 9 位文件码

#### 场景 B: 企业内网 / 家庭使用
```json
"EnableJoinRateLimit": false
```
**原因**: 用户可信，不需要限制

#### 场景 C: 高并发场景
```json
"EnableJoinRateLimit": true,
"JoinAttemptsPerMinute": 500
```
**原因**: 既防止攻击，又支持高并发

### 代码层面的改动

**SignalingOptions.cs**:
```csharp
/// <summary>
/// 是否启用入房速率限制。<b>默认关闭</b>以避免误伤正常用户。
/// </summary>
public bool EnableJoinRateLimit { get; set; } = false;
```

**SignalingEndpoints.cs**:
```csharp
// V2: 仅在 EnableJoinRateLimit=true 时启用限速
if (options.EnableJoinRateLimit && !limiter.TryRecordAttempt(...))
{
    // 返回 429
}
```

## 常见问题

### Q1: 所有国内 STUN 服务器都试过了还是连不上？

**可能原因**:
1. 本地防火墙阻止 UDP 3478 端口
2. 运营商限制 STUN 协议
3. 网络环境特殊（如某些企业网络）

**解决方法**:
- 临时关闭防火墙测试
- 联系网络管理员
- 部署自己的 TURN 服务器

### Q2: 关闭速率限制安全吗？

**内网环境**: ✅ 完全安全
- 用户可信
- 不暴露公网
- 无安全风险

**公网环境**: ⚠️ 建议开启
- 防止暴力枚举文件码
- 保护服务器资源
- 避免滥用

### Q3: 如何验证配置生效？

查看服务启动日志:
```
info: Microsoft.Hosting.Lifetime[0]
      STUN 服务器: stun:stun.miwifi.com:3478
      速率限制: 已禁用
```
