# NexusP2P 使用说明

**不需要装 .NET**，解压就能跑。只支持 Windows x64。

```
NexusP2P-Desktop.exe    图形界面（推荐，双击就用，不会弹命令行窗口）
nexusp2p.exe            命令行版（脚本、批量、远程登录时用）
nexusp2p.json           配置：信令服务器地址填在这里，两个版本共用
nexusp2p-signaling.exe  信令服务器（只需要一台跑，或者用你自己部署的）
start-signaling.cmd     局域网对测时用它起信令服务器（会自动填好本机 IP）
```

## 软件更新与安装包

桌面版的「设置 → 软件更新」从项目的 GitHub Releases 检查正式版本。发布时使用
`v主版本.次版本.修订号` 标签（例如 `v1.1.0`），Release 必须包含同版本的安装器：

```text
NexusP2P-Setup-1.1.0-win-x64.exe
```

推送符合格式的标签后，GitHub Actions 会测试项目、生成便携 ZIP 和 Inno Setup
安装器，并创建 Release。手动打安装器时先运行 `packaging/package.sh win`，再运行：

```powershell
.\packaging\build-installer.ps1 -Version 1.1.0
```

安装器按当前 Windows 用户安装到 `%LOCALAPPDATA%\Programs\NexusP2P`。以后从设置页
下载的新安装器会复用该目录并覆盖升级。

图形界面和命令行是**两个独立的程序**，功能完全一样（同一套传输内核），
用哪个都行、也可以一端用图形界面另一端用命令行。

> Windows 会弹「SmartScreen 已阻止」——没买代码签名证书，这是预期的。
> 点「更多信息」→「仍要运行」。

## 最省事的用法：图形界面

双击 `NexusP2P-Desktop.exe`。第一次打开如果还没配信令地址，它会直接把你
带到「设置」页。

**发送**：把文件或文件夹拖进窗口 → 点「生成文件码并等待对方」→
把「分享链接」发给对方。

**接收**：把对方给的链接粘进「接收」页 → 点「开始接收」。

几件值得知道的事：

- **关掉窗口不会中断传输**，程序缩到托盘继续传。鼠标悬到托盘图标上能看到进度，
  双击图标回到窗口。真要退出就用托盘右键菜单里的「退出」。
- 传输中断（拔网线、对方断电）会**自动重连 3 次**，界面上会显示「正在重连 2/3」。
- 进度是按**内容**记的，不是按连接。所以关掉程序、重开、重新要一次码，
  也能接着上次的进度传，不会从头再来。
- 界面上会写明当前**瓶颈在哪**（走中继 / 对方处理不过来 / 本机上行已满）。
  看到速度不理想时先看这一行，多半不是程序坏了。

## 先配一次 `nexusp2p.json`

打开 `nexusp2p.json`，把地址填进去：

```jsonc
{
  // 跨公网用你部署的域名；局域网对测用 start-signaling.cmd 打出来的那个地址
  "signaling": "https://p2p.你的域名"
}
```

**填好之后把整个文件夹拷到另一台电脑**，两边就都对了 ——
之后所有命令都不用再带 `--signaling`。

> 这个文件允许写 `//` 注释和尾逗号，随便加备注。
> 写坏了程序会明确告诉你是哪个文件、哪里不对，不会默默当成没配。

三种指定方式的优先级：**命令行 `--signaling` > 环境变量 `NEXUSP2P_SIGNALING` > 这个文件**。
临时想连另一台服务器，直接在命令行上带 `--signaling` 覆盖掉就行。

## 场景一：两台电脑在同一个局域网

> 下面用命令行演示，图形界面是同样的流程 ——
> 拖文件、拿链接、对方粘链接。

**A 电脑**：双击 `start-signaling.cmd`。它会打出一行地址，比如
`信令服务器：http://192.168.1.10:5000`，**把这个地址记下来**。

> 首次运行 Windows 防火墙会弹窗，**必须点「允许」**。
> 不允许的话对方连不上，而且没有任何提示，只表现为「一直连不上」。
>
> 探测到的 IP 不对（比如挑了虚拟网卡）时，脚本会把本机其他 IPv4 都列出来，
> 换一个再来：`powershell -File start-signaling.ps1 -Ip 192.168.1.20`

把那个地址填进两台电脑的 `nexusp2p.json`，然后 **A 电脑**（另开一个窗口）发送：

```
nexusp2p.exe send D:\要传的文件.zip
```

它会打出两样东西：

```
  文件码：130-226-582
  分享链接：http://192.168.1.10:5000/r/130226582
```

**B 电脑**接收，念一遍文件码就够了：

```
nexusp2p.exe receive 130-226-582 --dest D:\收到
```

> 不需要密钥 —— 它会在连接建立后由发送方自动送过去。
> 贴分享链接也行：`nexusp2p.exe receive "http://192.168.1.10:5000/r/130226582" --dest D:\收到`

## 场景二：两台电脑在不同的网络（跨公网）

需要一台有公网 IP 的机器跑信令服务器，并且**建议配上 coturn 中继**，
否则打洞失败就连不上。

Linux 服务器用另一个包：`nexusp2p-signaling-linux-x64.tar.gz`，
里面有 systemd 单元与 nginx 反代配置，见包内的「部署说明.md」。

服务器起好之后，把两台电脑的 `nexusp2p.json` 改成你的域名：

```jsonc
{ "signaling": "https://p2p.你的域名" }
```

命令和局域网那节完全一样。

## 连上之后看哪一行

```
已连接（同局域网直连）。开始传输。
```

括号里就是当前走的路径，**速度慢的时候先看这里**：

| 括号里写的 | 含义 |
|---|---|
| `同局域网直连` | 最快，走的是内网 |
| `打洞成功，公网直连` | 跨公网直连，没经过服务器 |
| `经服务器中继，速度受服务器上行带宽限制` | 打洞失败，在走中继。慢是正常的 |

## 断了怎么办

**什么都不用做。** 断线会自动重连 3 次，界面上会显示第几次。

3 次都失败才会退出。这时**重新运行一模一样的那条命令**即可接着传 ——
进度是按内容记的，跟这次连接、这个文件码都无关。会看到：

```
（其中 1.20 GiB 是上次留下的，本次续传）
```

Ctrl+C 主动中断也一样，已收到的部分保留在磁盘上。

> 已收到的部分存在接收目录下的一个工作子目录里，收完才移到最终位置。
> 确定不传了，把它删掉就行。

## 连不上，按这个顺序查

1. **`curl http://<A的IP>:5000/health`**（在 B 电脑上跑）——
   连不上说明是防火墙或 IP 填错，跟 P2P 无关
2. **文件码提示不可用** —— 链接没加引号被截断了，或者发送端已经退出了
3. **两端都停在「等待对方接收」/「正在连接」** —— 检查 A 的防火墙是否放行了 `nexusp2p.exe`
   本身（不只是信令端口，WebRTC 还要 UDP）
4. **跨公网连不上** —— 大概率是没配中继，见 `deploy/README.md`
