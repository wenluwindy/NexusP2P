#### 阶段 3 查出的问题

都是「**卡死且两端都不报错**」这一类 —— 单测全绿，接上真网才暴露：

| 问题 | 症状 | 修法 |
|---|---|---|
| 数据通道在上层订阅前收到的消息被丢弃 | 重连后清单发出去没人收，两端干等 | 订阅前攒住，订阅时按序补发 |
| 信令在处理器挂上前收到的 SDP 被丢弃 | 接收端建 WebRTC 对象要几百毫秒，这期间的 offer 消失 | 同上，加显式开闸 |
| `WaitForOpenAsync` 没有超时 | ICE 打不通时永远停在「等待对方接收」 | 与 answerer 侧对称地加上 |
| `WaitForDrainAsync` 的 catch 写在循环外 | 低水位回调晚于 200ms 就假装排空完成，背压失效 | catch 挪进循环 |
| 连接超时不算可重试 | AD-7 承诺的自动重连在最典型的场景下一次都不发生 | `TimeoutException` 与信令网络故障算可重试 |
| CLI 输出用控制台默认编码 | Windows 上中文与路径全是乱码 | 强制 UTF-8 |

#### 阶段 4 的设计偏离：WPF 而不是 WebView2

AD-3 原计划让前端只写一遍，exe 用 WebView2 加载同一份产物。实际做的时候
改成了原生 WPF，原因：

| | WebView2 方案 | 原生 WPF（实际采用） |
|---|---|---|
| 运行时依赖 | 需要 WebView2 Runtime（Win10 部分版本没有） | 无 |
| 需要的额外代码 | 本地 HTTP 宿主 + 本地 API + JS/.NET 桥 | 无 |
| 拖放与文件对话框 | 要绕 WebView2 的限制 | 系统原生 |
| 前端代码复用 | 是 | 否（多一份 UI 要维护） |

决定性的一点是：**exe 的传输必须跑在 .NET 后端**（大文件流式落盘、
跨会话续传、关窗后继续传，这些浏览器给不了）。所以 WebView2 里那份前端
无论如何都只能当一层壳，得靠本地 API 把活派给 .NET —— 那层 API 与 JS 桥
纯属为了复用 UI 而付的代价，而它的体量比直接写一个 WPF 界面还大。

代价是诚实的：**两份 UI 要各自维护**。共用的是它们下面那一整套
（协议、加密、清单、重连），UI 层本来就只是薄薄一层。

#### 踩到的坑

| 问题 | 症状 | 修法 |
|---|---|---|
| 桌面版 `AssemblyName` 取成 `NexusP2P` | 打出的包里**根本没有图形界面** —— Windows 文件名大小写不敏感，`NexusP2P.exe` 与 CLI 的 `nexusp2p.exe` 是同一个文件，后发布的静默覆盖前一个 | 改名 `NexusP2P-Desktop.exe` |
| 从 `Directory.Build.props` 继承了 `InvariantGlobalization=true` | **中文 Windows 上一输入文字就崩**：WPF 的 IME 路径会 `new CultureInfo(2052)`，invariant 模式下直接抛「2052 (0x0804) is an invalid culture identifier」 | 桌面版工程显式 `<InvariantGlobalization>false` |
| `OnStartup` 里 `new MainWindow()` 没有 try/catch | 窗口建失败时 `DispatcherUnhandledException` 兜住并标记已处理，于是留下一个**没有窗口、没有托盘、也关不掉**的隐形进程 | 启动单独 try/catch，失败就真的 `Shutdown()`；异常处理器按「界面在不在」决定能否继续 |
| 空闲时关窗静默缩到托盘 | 用户以为程序退了，而托盘图标常被折叠进「显示隐藏的图标」——「这软件关不掉」 | 首次缩托盘必提示；设置页加一个明确的「退出程序」按钮 |

##### `InvariantGlobalization` 这个坑为什么特别难查

两个性质叠在一起，让它躲过了全部既有测试：

1. **只在中文界面的机器上出现。** 英文界面 LCID 1033 走 invariant 路径不报错，
   所以在英文 Windows 上开发/CI 完全看不到。
2. **只在输入文字时触发**，光启动程序没事。

而当时的冒烟测试断言的是「进程还活着」—— 异常被兜住之后进程确实还活着，
测试于是**报告通过**，而界面已经坏了。

教训写进测试里了：`ProjectConfigurationTests` 直接读 csproj 断言这个属性，
不依赖能不能复现（用 SendKeys 模拟输入去复现是不稳定的，试过，时序会飘）。
| WinForms 的隐式 using | `Application`、`DragEventArgs` 等在每个文件里都变成歧义 | csproj 里 `<Using Remove>` 掉，WinForms 只在 `TrayPresence.cs` 显式引入 |
| `rm -rf` 打包目录在 Windows 上失败 | 残留的 MSBuild 常驻进程持着句柄，打包脚本直接报 `Device or resource busy` | 只清空目录内容，不删目录本身 |
